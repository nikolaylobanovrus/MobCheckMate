# Чек-лист публикации в Google Play

Требования на 17.09.2026. Перед каждым релизом сверять с официальной документацией Google, сроки меняются.

## 1. Аккаунт
- [ ] Решить тип аккаунта: Organization (при наличии юрлица) или Personal.
- [ ] Для Organization: получить D-U-N-S, подтвердить сайт и телефон.
- [ ] Для Personal: паспорт, подтверждение адреса (счёт за коммунальные услуги, выписка банка), Android-устройство.
- [ ] Оплатить $25 картой, которая не является предоплаченной.
- [ ] Пройти верификацию личности. Имя и адрес в профиле должны совпадать с документами.
- [ ] Если разработчик из России: проверить на практике, проходит ли верификация (см. ROADMAP, раздел 5.1).
- [ ] Если нужны выплаты: merchant-аккаунт на юрлицо вне России (не Грузия).

## 2. Сборка
- [ ] `compileSdk` и `targetSdk` 36.
- [ ] Формат AAB, Play App Signing включён, upload key хранится отдельно от ключа подписи.
- [ ] 64-битные архитектуры (arm64-v8a, x86_64), если есть нативный код.
- [ ] Страницы памяти 16 КБ: NDK r28+, AGP 8.5.1+; проверка `zipalign -c -P 16 -v 4 app.apk`.
- [ ] Edge-to-edge поддерживается без отключения.
- [ ] Play Billing Library 8+ (если есть покупки).
- [ ] Play Games Services только v2 (если используются).
- [ ] UMP SDK для согласия на рекламу в ЕЭЗ, Великобритании и Швейцарии (если есть AdMob).
- [ ] `app-ads.txt` на сайте разработчика (если есть AdMob).
- [ ] Play Integrity API на сервере для рейтинговых партий.

## 3. App content
- [ ] Политика конфиденциальности: публичный URL, не PDF, ссылка и в консоли, и в приложении.
- [ ] Data safety: перечислены все собираемые данные (ID пользователя, ник, e-mail, IP, история партий, данные
      рекламного SDK). Проверить, что совпадает с реальным трафиком.
- [ ] Удаление аккаунта: внутри приложения и через веб-страницу, данные реально удаляются на сервере.
- [ ] Анкета возрастного рейтинга IARC.
- [ ] Декларация рекламы.
- [ ] Целевая аудитория — не дети. Иначе действует политика Families и запрещён анонимный чат.
- [ ] Разрешения: только необходимые, каждое обосновано.
- [ ] Турниры: нет платного входа с призами реальной ценности; призы за билеты только виртуальные и не выводятся.
- [ ] Шансы показываются до покупки, если награда за покупку случайная.

## 4. Витрина
- [ ] Название до 30 символов, краткое описание до 80, полное до 4000; без повторов ключевых слов.
- [ ] Иконка 512×512, 32-bit PNG с альфа-каналом, до 1 МБ.
- [ ] Feature graphic 1024×500, JPEG или 24-bit PNG без альфа-канала.
- [ ] Скриншоты телефона: минимум 4 в 1080×1920 (для рекомендаций), первые 3 — самые сильные.
- [ ] Скриншоты планшета 16:9 или 9:16 (если поддерживаем планшеты).
- [ ] Промо-видео на YouTube без рекламы и возрастных ограничений.
- [ ] Локализация витрины: RU, EN + ES, PT-BR, HI.
- [ ] Контакт поддержки: e-mail, сайт.

## 5. Тестирование
- [ ] Internal testing (до 100 человек).
- [ ] Pre-launch report без падений. Для игровых экранов добавить игровой сценарий (game loop), иначе краулер не
      пройдёт дальше меню.
- [ ] Closed testing для Personal-аккаунта: не меньше 12 тестировщиков непрерывно 14 дней. Набирать 15–20 с
      запасом: вышедший и вернувшийся тестировщик обнуляет свой отсчёт. Тестировщики должны реально играть.
- [ ] Заявка «Apply for production» (рассмотрение до 7 дней).
- [ ] Open testing — по желанию. Ключ подписи фиксируется навсегда при первой публикации в открытый трек.

## 6. Релиз
- [ ] Первый релиз в production выкатывается на 100 % (поэтапный выпуск доступен только для обновлений).
- [ ] Обновления: 5 % → 20 % → 50 % → 100 %, с остановкой при росте падений.
- [ ] Android Vitals: падения не выше 1,09 %, ANR не выше 0,47 %.
- [ ] Ответы на отзывы с 1–3 звёздами в течение 48 часов.
- [ ] Заявка на фичеринг в первые 120 дней после запуска.

## 7. Частые причины отказа
- Data safety не совпадает с реальным трафиком.
- Нет удаления аккаунта внутри приложения.
- Недоступная политика конфиденциальности.
- Падения и ANR в pre-launch report.
- Лишние разрешения «на будущее».
- Нет feature graphic или он неверного размера.
